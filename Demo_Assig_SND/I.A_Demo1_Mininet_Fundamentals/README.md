# Demo1 — Mininet Fundamentals

## Learning Goal
The main objective of this demonstration is to get familiar with Mininet as an SDN emulation environment. By doing this assignment, students will master both Mininet's CLI and Python API. Besides, students will also learn to create fast prototyping topologies.

## Setting Up

In this course, we will be using ONOS as an SDN controller along with some dependencies: Docker, OVS, Mininet, and a Linux machine.

It is noted that networking knowledge, familiarity with Linux shell bash, and Python are considered prerequisites.

Before starting Task 1 to Task 3, complete Task 0 in `Task0_Env_setup/01 Install_guide.md`.

## Task 0: Environment Setup

- Install and verify Docker, OVS, Mininet, and ONOS.
- Confirm that the ONOS UI and REST API are reachable.
- Use the shared cleanup scripts before rerunning experiments.

See `Task0_Env_setup/01 Install_guide.md` for the full setup guide.

## Tasks

### Task 1: CLI Topologies with Local and Remote Controllers
- Create three standard topologies using the Mininet CLI
- Use both the OpenFlow reference controller and ONOS
- Record commands, explanations, and validation results

Task description:
- Create a single-switch topology with 10 hosts.
- Create a linear topology with 5 switches and 5 hosts.
- Create a tree topology with depth 3 and fanout 2.
- Repeat the same tasks with ONOS as the remote controller.

Expected result:
- All requested CLI topologies start successfully.
- The correct switches and hosts appear in Mininet.
- ONOS-based runs are visible in the controller UI or REST API.

### Task 2: Python API Topologies with ONOS
- Build three topologies using the Mininet Python API
- Connect them to ONOS as the remote controller
- Validate connectivity and ONOS discovery

Task description:
- Create a single-switch topology with 13 hosts.
- Create a linear topology with 10 switches and 10 hosts.
- Create a tree topology with depth 3 and fanout 2.
- Use low-level, mid-level, high-level API calls, or a mixture of them.

Expected result:
- Each Python script creates the intended topology successfully.
- Hosts and switches appear correctly in Mininet.
- ONOS discovers devices, links, and hosts for each run.

### Task 3: Automating Task 2 Topologies
- Automate topology generation from input parameters
- Support at least linear and tree topology types
- Clean up before rerunning a new generated topology

Task description:
- Build an automation script that can create a topology from the requested type and its specifications.
- Reuse the ideas from Task 2 instead of writing one fully separate script per topology.
- Demonstrate at least one linear topology and one tree topology generated by the same automation approach.

Expected result:
- The automation accepts topology type and parameters.
- Multiple topology variants can be generated from one implementation.
- Cleanup and rerun work without stale topology conflicts.

## Evidence Required
- Topology creation output (h1 IP, switch list)
- Ping connectivity evidence per task
- Brief explanation of each topology's use case
- Brief note on issues faced and how they were resolved
